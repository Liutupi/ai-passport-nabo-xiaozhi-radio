# 固件移植计划

目标：把浏览器原型的《NABO 牌桌》搬到 AI Passport 徽章（ESP32-C3，240×320，三键），沿用深潜的做法。

## 1. 现状（实测）

| 项目 | 数值 | 来源 |
|---|---|---|
| app 分区 | 4,128,768 字节，已用 4,107,808，**剩约 20 KB** | `partitions/ai_passport_nabo.csv`、v1.3.0 `xiaozhi.bin` |
| assets 分区 | 3 MB，已用 1.3 MB，**剩约 1.7 MB** | v1.3.0 `assets.bin` |
| 可删的 app 代码 | 骰子 14.7 KB、木鱼 4.2 KB、快捷键 7.6 KB、深潜 106.8 KB | 编译后 `.text` |
| 游戏运行时内存 | 约 45 KB（深潜实测） | 深潜移植记录 |
| 精灵（按原型截取、全帧） | 大图约 2.6 MB + 小图约 0.9 MB | `tools/clip_to_sprites.py` 报告 |

## 2. 精灵怎么存、怎么画

- **放 assets 分区**。xiaozhi 已有现成接口 `Assets::GetAssetData(name, ptr, size)`，整个分区已经映射到内存地址，读取不占 RAM。打包时把 `table_sprites.bin` 放进 `DEFAULT_ASSETS_EXTRA_FILES` 目录，构建会自动打进 `assets.bin`。
- **格式沿用徽章现有 NABO 头像的做法**（`muse_pixel.c`）：每帧带调色板，有一张行偏移表，像素用行程编码（RLE），可以逐行解码，不需要整帧解压缓冲。这里再加两点：
  - 调色板索引 0 表示透明，透明区直接跳过，露出程序画的绒布和墙。
  - 半透明的边缘像素预先和深色背景混合好，固件里不做 alpha 混合。
- **只出用得到的尺寸**：大图（150 px）只用于封面、交接屏、整场结束；小图（72 px）只用于对局顶部。
- **压帧数**：待机循环从 36 帧压到 12–16 帧，展牌压到 8 fps。目标总量控制在约 1.2 MB 以内，留出余量。
- 生成脚本：`tools/generate_table_sprites.py`，输入 `nabo-table/sprites/`，输出 `table_sprites.bin` 和一个小的 C 头文件（动作名 → 帧号、fps、是否循环、事件帧）。

### M1 结果（2026-10-18，已完成）

- 生成脚本：`ai-passport-nabo-xiaozhi-table/tools/generate_table_sprites.py`，输出 `table_assets/table_sprites.bin` 和 `nabo_table_sprites.h`。
- 16 个动作、227 帧，**共 847 KB**，占 assets 剩余空间（约 1.7 MB）的一半。
- 实测下来，单纯行程编码压不动视频帧（视频噪点让相邻像素很少相同，全部算下来要 1.5 MB）。最后用的方案：
  - 每个动作共用一套 64 色调色板；
  - 第 0 帧是关键帧（行程编码），之后每帧只记录和上一帧不同的像素（跳过 / 新像素两种标记）；
  - 颜色变化很小的像素沿用上一帧的颜色，既去掉视频闪烁，也让差分帧更小。
- 试过众数滤波：压缩更狠，但 72 px 下眼镜和五官会被抹掉，所以不用。
- 每帧都会从 .bin 解码回来，和源帧逐像素比对，颜色误差超过阈值就报错。
- **内存**：播放时每个动作要一块 宽×高 字节的索引缓冲。最大的是封面展牌（179×167，约 29 KB），其余大图约 17 KB，小图约 4–5 KB。封面上同时只放一个动作，但 29 KB 仍然偏紧，M3 时实测；不够就把展牌的扇面裁窄一些。

### M2 结果（2026-10-18，已完成）

- `nabo_table_model.c/.h`：封面、交接屏、暂停、比赛流程、21 点；`nabo_table_bid.c`：大话骰的摇骰、两步叫数、开盅计数（1 点万能 / 斋）。纯逻辑，不依赖屏幕、声音和 RTOS。
- 随机数用和原型一样的 mulberry32，时间用 double，所以同一个种子、同样的按键，结果和原型一模一样。
- 对拍：在浏览器原型里用 `tests/table_host/record_golden.js` 录了 6 条轨迹，共 3200 步，涵盖两种玩法、57 局、26 次开盅、平局、整场结束、暂停，以及不同骰子数和万能规则。`test_table.py` 用 C 逐步重放，每一步状态都和原型一致。
- 另有 4 条规则测试：抢局设置、只有对局中能暂停、首叫没有「开」、斋。故意改坏三条规则做了检验：都能被测试抓到。

### M3 结果（2026-10-18，已完成）

- 渲染器：`nabo_table_gfx.c` 每帧生成绘制操作列表，和上一帧比对出变化的矩形，只重画这些区域，每次合成 8 行再送屏。全部用整数运算（C3 没有浮点单元）。
- 形状：`nabo_table_shapes.c` 画绒布和桌沿、抗锯齿圆角矩形、四种花色、牌面（角标、点数排布、人头牌面板）、牌背、翻牌压扁效果和骰盅。
- 骰子：在 `nabo_dice_render.c` 里加了"在任意位置摆一颗骰子"的接口，复用摇骰子 app 的光照；摇骰子 app 原来的 63 个测试照样通过。
- 画面：`nabo_table_scene.c`（封面、交接屏、结束、暂停）和 `nabo_table_scene_play.c`（两张牌桌），坐标照搬原型。
- 字体：新增 `nabo_table_font_12`（提示和标签）和 `nabo_table_font_24`（只有 9 个大字）。徽章原本最小的中文字号是 16 px，原型里 9–11 px 的小字都改用这个 12 px 字体。
- 素材包调整：大图改成每帧都是关键帧，可以直接从 flash 解码，不占内存；小图仍用差分帧。总共 1.18 MB。**精灵缓冲只要 5.3 KB。**
- 测试：主机上用真实 C 渲染出所有画面，和原型对照过；按一局录好的对局逐帧播放 1000 多帧，增量重画和整屏重画逐像素一致。
- 还没测的：在 C3 上的实际速度（M4 上板时实测）。

### M4 结果（2026-10-18，已上板，待手感验证）

- 牌版仓库删掉了骰子、木鱼、电脑快捷键（连同蓝牙主机 `nabo_pc.c`）和深潜；工具箱里新增「NABO 牌桌」，语音「打开牌桌 / 大话骰 / 二十一点」也能打开。
- `nabo_table.c`：独立任务，30 fps；直接读按键的按下和松开：UP/DOWN 按住连发，OK 松开生效，按住 2 秒暂停。牌桌里双击上键不会退出；长按上键只在牌桌封面上才退回主页，免得按住上键翻叫数时被踢出去。
- `nabo_table_sound.c`：现场合成，骰子敲击沿用摇骰子 app 的共振器，纸牌声用滤波噪声，开盅和获胜用铃声。
- 构建：同步到卷外目录后运行 `tools/build.py`（见固件仓库 docs/BUILD.md）。app 0x399A40，app 分区还剩约 346 KB；assets 2.54 MB / 3 MB。
- 烧录：第二块徽章。先整片备份到本机，确认分区表和构建完全一致后，写入 app 和 assets，哈希校验通过。
- 实测：28–30 fps；平时每帧 1.5–6.5 ms；整屏重画 55–180 ms（只在换画面时出现，会有一下短暂的停顿）；打开后空闲内存约 65 KB，最大连续块 34 KB。新加了 `>table.capture` 串口截屏，抓回来的真机画面和主机渲染一致。
- 已知：这块徽章没配 Wi-Fi，开机后要等约 60 秒进入配网模式，之后才能打开本地程序。这是原有固件的行为，不是牌桌的问题。
- 还没验证：按键手感、声音，以及能否连续玩完一整场。
- 后续修改（同日）：
  - 叫数显示放大：数字改用 28 px 粗体，骰子 24–30 px。
  - 开机后不用等小智联网就能进本地程序：`application.cc` 在 NABO 板型下允许在 starting / wifi_configuring 状态打开；关闭时接着走开机流程，如果期间连上了网，就补发一次联网事件去激活。真机验证过：开机 17 秒就打开了牌桌，退出后照常进入配网模式；配网模式下也能反复进出。
  - 「联网后再激活」这条路径还没在真机上验证：第二块徽章没有可用的 Wi-Fi。
  - 牌桌封面上双击上键或长按上键可以退出；对局中这两个操作都屏蔽，防止翻叫数时误退。对局中要退出：长按 OK 暂停 → 回到封面 → 双击上键。

## 3. 代码模块（每个文件控制在 400 行以内）

| 文件 | 内容 | 能否在电脑上测 |
|---|---|---|
| `nabo_table.c` | 打开 / 关闭 / tick / 按键，内存分配，和 `nabo_apps.cc` 对接 | 否 |
| `nabo_table_model.c` | 状态机：封面、交接屏、21 点、大话骰、暂停、结算；用和原型相同的 mulberry32 随机数 | **能**：同一个种子，结果要和原型一致 |
| `nabo_table_bid.c` | 两步叫数、合法性、开盅计数（1 点万能 / 斋） | **能** |
| `nabo_table_draw.c` | 各画面的排版，按行带输出 | 能（主机渲染成 PNG） |
| `nabo_table_cards.c` | 扑克牌正面、牌背，程序绘制 | 能 |
| `nabo_table_sprites.c` | 从 assets 读精灵，逐行 RLE 解码 | 能（读文件代替映射） |
| 复用 `nabo_dice_render.c` | 立体骰子：拆出"画一颗静止骰子"的函数 | 能 |
| `nabo_table_sound.c` | 骰子敲击复用 `nabo_dice_sound_*`；纸牌声用滤波噪声 | 能（输出 WAV） |

不做：小智语音对局、MCP 叫数（以后再说）。保留：语音或 MCP 打开 app（`>apps.open=table`、"打开牌桌"）。

## 4. 测试与验证（照深潜）

- `tests/table_host/`：主机上直接编译 model、bid、draw，渲染出和屏幕一致的帧（PNG）；用固定种子把整局走完，和原型的 `TABLE.state()` 对比发牌和骰子结果。
- 串口命令：`>apps.open=table`、`>table.press=up|down|ok`、`>table.hold=ok,2100`、`>table.state`、`>apps.capture`。
- 真机：先用 `>table.auto=1` 自动对局跑一段时间，看帧率、内存余量、有没有卡顿。

## 5. 里程碑

1. **M1 精灵打包**：生成 `table_sprites.bin`，主机解码回 PNG，逐像素对比 → 确认格式和大小。
2. **M2 逻辑**：model + bid 在主机跑通，和原型逐局对拍。
3. **M3 画面**：主机渲染各画面截图，和原型并排检查。
4. **M4 上板**：接入 `nabo_apps.cc`，替换骰子 app 的位置，构建、烧录 app + assets，串口截屏。
5. **M5 声音与手感**：音效、按键连发、长按暂停，真机调。
6. **M6 发布**：打包、校验、写更新说明。
