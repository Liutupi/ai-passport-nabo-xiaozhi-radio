# 《NABO 牌桌》设计文档（工作标题）

AI Passport 徽章（ESP32-C3，240×320 竖屏，三键 UP / DOWN / OK）上的 2–4 人同机游戏合集（最初为两人设计，第 9 节记录多人改动）。
两个真人传着一台徽章玩，NABO 是荷官和裁判，不参与对局。

## 1. 整体结构

```
封面：NABO 荷官待机（洗牌 / 摇盅循环）
 ├─ 21 点
 ├─ 大话骰
 └─ 设置：抢几局（3 / 5 / 7）、音效开关
```

- 封面 UP / DOWN 选桌，OK 进入。
- 每桌都是**抢局制**：先赢满设定局数的玩家获胜（默认抢 3）。平局不计分，直接重来。
- 对局中长按 OK 2 秒 → 暂停菜单（继续 / 回封面）。
- 每局结算时底部给两个选项：「下一局」（打满局数时是「看总比分」）/「回封面」，UP / DOWN 切换。
- 整场结束画面：「再来一场」/「回封面」。
- 交接屏和私密回合的提示行都带「长按 OK 暂停」，让玩家知道怎么中途退出。

## 2. 交接屏（两个玩法共用，防偷看）

一台设备两个人用，轮到谁，谁才能看到自己的牌或骰子。

1. 每次换人，先出现交接屏：NABO 捂眼，文字「交给 玩家 2 · 准备好按 OK」。
2. 按 OK 之后才显示该玩家的私密信息。
3. 该玩家操作完，画面自动盖回，进入下一个交接屏。
4. 交接屏上**不显示任何私密信息**，只显示公开信息（比分、对方已有几张牌、当前叫数）。

玩家用颜色区分：玩家 1 暖色，玩家 2 冷色。交接屏、比分、提示条都带上对应颜色。

## 3. 21 点（两人对决，无庄家，无明牌）

### 规则

1. 每局一副 52 张牌重新洗，每人发 2 张，**全部盖着**。
2. 先手每局轮换（第 1 局玩家 1），之后两人轮流行动，每回合二选一：
   - **要牌**：再拿 1 张（盖着）；
   - **停牌**：本局不再要牌，之后轮到他时自动跳过。
3. 两人都停牌（或爆牌）后统一开牌。
4. 点数：A = 1 或 11（自动取对自己最有利的值），J / Q / K = 10。
5. 判定：
   - 一方超过 21（爆牌），另一方没爆 → 没爆的赢；
   - 都没爆 → 接近 21 的赢；
   - 点数相同或两人都爆 → 平局；
   - 拿到 21 点也不会自动停牌，玩家自己决定（防止暴露信息）。
6. 爆牌时**不提示对手**：爆了的玩家自己能看到，但为了不泄露信息，仍然要按「停牌」并经过交接屏。

公开信息：每人面前盖着几张牌、谁已停牌。这是唯一的心理战线索（"他要了 4 张还没停……"）。

### 操作（私密界面）

| 键 | 作用 |
|---|---|
| UP / DOWN | 在「要牌」「停牌」之间切换 |
| OK | 确认 |

私密界面显示：自己的所有牌、当前点数（软 / 硬点数都标出）、对手的牌数。

## 4. 大话骰（两人，保留叫数）

### 规则

1. 每人 5 颗骰子，每局双方各自摇盅（由设备随机），只在自己的私密界面看。
2. 上一局的输家先叫；第一局玩家 1 先叫。
3. 叫数格式：「N 个 X」，意思是**两人合起来**至少有 N 颗点数为 X 的骰子。
4. 后叫的必须比上一个大：数量更多，或数量相同点数更大。1 点万能时，1 算最大的点数（同数量下「N 个 1」最大）。
5. 也可以不叫，选择「开」：开盅统计双方骰子。
   - 实际数量 ≥ 叫数 → 叫数方赢；
   - 实际数量 < 叫数 → 开的一方赢。
6. **1 点是万能点**，可以当作任何点数统计；但如果有人叫的是「N 个 1」（称为"斋"），本局 1 点不再万能。
7. 起叫最少 2 个（两人共 10 颗骰子，叫 1 个没有意义）。

可调参数（原型里做成滑杆，定稿后写死）：每人骰子数、起叫数量、1 点是否万能。

### 叫数操作

叫数分两步，每步都只用 UP / DOWN / OK：

1. **选数量**：画面显示「[4] 个 [?]」，UP 加、DOWN 减。默认停在最小的合法数量。从最小数量再按 DOWN 是「开！」（首叫时没有）。
2. **选点数**：OK 后右边的格子亮起，UP / DOWN 换点数，只列出比上一个叫数大的点数；能沿用上一个点数时默认就停在它上面。从最小点数再按 DOWN 是「返回」，回到第 1 步改数量。OK 叫出。

```
  ▲               ▲
 [ 5 ]  个  [ ⚂ ]      OK 叫出「5 个 3」
  ▼               ▼
```

早期原型用的是一条升序长列表，从「2 个 2」一路往下翻，叫大数要按很多次，还容易让人以为只能叫 2 个，所以改成两步。

私密界面显示：自己的 5 颗骰子、上一个叫数（大字）、叫数历史。

## 5. NABO 的演出（荷官 / 裁判）

| 时机 | NABO 动作 |
|---|---|
| 封面待机 | 洗牌 / 摇盅循环 |
| 发牌 / 摇盅 | 发牌、摇盅动作 |
| 交接屏 | 捂眼，提示交给谁 |
| 开牌 / 开盅 | 喊「开！」，掀盖 |
| 一局结束 | 指向赢家，赢家颜色彩带 |
| 整场结束 | 举冠军奖杯，显示比分 |
| 爆牌 / 开中 | 夸张的惊讶表情（开牌后才演，不泄露信息） |

美术流程沿用深潜：Codex 用骨骼拼接（SVG 部件 + 渲染脚本）出帧，提示词里直接写 NABO。具体规格之后写在 `ART_BRIEF.md`。

## 6. 技术约束与预算

- 屏幕 240×320 竖屏，RGB565；三键共用一个 ADC 引脚，**不能同时按两个键**。
- 扑克牌和骰子用代码绘制（点数、花色、骰点），不占图片资源；NABO 动画帧是主要的资源开销。
- 骰子沿用固件摇骰子 app（`nabo_dice_render.c`）的立体渲染：象牙白圆角、左上光源和高光、中式红色 1/4 点、凹坑点；牌桌这里俯视角从 47° 改为 58°，让朝上的点数一眼可读。音效沿用它的阻尼共振器木质敲击声（16 kHz），摇盅、扣盅、落桌都用它；纸牌音（发牌、翻牌、洗牌）用滤波噪声合成。原型实现见 `prototype/dice3d.js`、`sound.js`、`cards.js`。
- 计划替换固件里现有的「骰子」app 位置，复用它的摇骰渲染。flash 预算：骰子 app 编译后约 15 KB，加上分区剩余约 18 KB；不够时再让出木鱼 / 快捷键 / 深潜（合计约 133 KB）。
- 运行时内存参照深潜：游戏打开时约 45 KB 可用。双人同机，无联网、无 AI，不需要小智在线。

## 7. 开发流程

1. **浏览器原型**（`prototype/`）：240×320 画布，键盘映射三键；把交接屏、发牌、叫数列表的手感调好。
2. **美术**：写 `ART_BRIEF.md` 和 `CODEX_PROMPTS.md`，交给 Codex 出 NABO 荷官动画。
3. **固件移植**：替换骰子 app，按深潜的方式加入 host 测试和串口调试命令。

## 9. 多人（2–4 人，2026-10-18）

封面多一项「N 人」（2 / 3 / 4，存 NVS `table_players`）。人数在开局时固定（`nt_t.np`）。

- **座位与传递：** 工牌按 1 → 2 → 3 → 4 传。两人保留左右两列；三、四人公开牌桌是 2 × 2 格子（左列 x 8、右列 x 124、宽 108；三人时第三位在第二行居中），单号在左、双号在右，NABO 朝右指 2、4 号。顶部比分也按左右排：1、3 号在左，2、4 号在右。
- **颜色：** 玩家 3 粉 `#FF6FA8`，玩家 4 绿 `#8EDB5A`（绒布是深绿，亮绿仍可读）。
- **21 点：** 从先手起轮流每人两张；轮到的人结束后交给下一个未停牌的人，其他人都停了就不交接。不爆的最高点数赢，并列最高都 +1；全爆或所有人同点为平局（这样两人局的规则与原来完全一样）。到达目标时若并列领先，加赛到有人单独领先。牌堆空了只能停牌（理论兜底：四人最多 44 张）。
- **大话骰：** 罚分制。开盅后错的一方罚 1 分，先罚满目标的人输，罚分者下局先叫。起叫 = max(设置值, 人数)；数量上限 = 每人骰子 × 人数（叫数上限 160 条、数量列表 25 项）。两人时与"先赢满 N 局"等价。
- **结束画面：** 21 点写"玩家 N 获胜"；大话骰两人写获胜者，三人以上写"玩家 N 输了 · 先罚满 N 次"（不举奖杯），下面一排是每人的分数。
- **渲染预算：** 四人六骰开盅时 24 颗骰子 + 叫数标签里 1 颗，显示列表峰值约 51 项；上限设为骰子 26、显示列表 80、扑克牌 48。
